# Structured Office editing

AI Office opens `/api/presentations/sections/ui` (also `/api/presentations/editor/app`) on a real editable document in the shared editor foundation. The original outline generator, themes, brand rendering, storage delivery and audience surfaces remain available through **Generation & delivery** (`?legacy=1`) and the existing audience URLs. Existing generated-file links import the actual saved file; they do not regenerate its outline.

| Document | Direct editing | Durable output |
| --- | --- | --- |
| PowerPoint | Select text boxes, rectangles, ellipses, images and tables; type rich text and table cells; drag, resize and rotate objects; change geometry in points, typography, fill, outline, opacity and shadow; insert, duplicate, arrange and reorder slides/objects. | Actual PPTX shapes, text runs, pictures and tables generated by the existing pinned `pptxgenjs` library. |
| Word | Edit rich paragraphs and exact text selections on explicit pages; insert/edit tables and PNG/JPEG images; change typography, heading/list styles, spacing, image size, page dimensions, margins, headers and footers; reorder blocks/pages. | Actual DOCX paragraphs, runs, tables, images and page sections generated by pinned `docx`. |
| Excel | Edit cells/formulas, select ranges, type or paste TSV, move with arrow/Tab keys, format typography/fills/borders/numbers and row/column sizes, add/reorder sheets and enlarge the grid. | Actual XLSX cells, formulas with calculated results, styles and dimensions generated by pinned `exceljs`. |

The workbook calculator supports arithmetic, comparisons, concatenation, percent, references/ranges including cross-sheet references, and `SUM`, `AVERAGE`, `MIN`, `MAX`, `COUNT`, `COUNTA`, `IF`, `ABS`, `ROUND`, `AND`, `OR`, `NOT`. Cycles and unsupported formulas display explicit errors. Formula text remains editable and is exported as a formula. Native Excel can calculate functions beyond this browser calculator.

## Save, history and authority

Each saved document has stable page/object/sheet IDs, its original owner's namespace and immutable numbered revisions. Manual Save and approved AI operations use the same model validator and compare-and-swap revision check. A retry key seals the original operation; a stale revision retains the browser draft. Saved history supports viewing an older revision, saving a copy, or explicitly restoring it as a new revision. Manual undo/redo includes an accepted assistant revision. Deletion explicitly removes the selected document, its revisions and retained original.

The new `authorization.yaml` declares named original-person `document.*` permissions and separate `legacy.access`; it does not grant or migrate access by itself. Install/catalog changes and any role assignment require the existing authorized installation flow. The old catalog-less `@app-admin` assignment is not silently mapped to this catalog: an operator must explicitly review and approve `admin` (full Office administration), `editor` (editing/export plus retained generation and delivery), or `viewer` (read only). Existing source files remain owned by their original people; adding the catalog does not itself migrate legacy files into structured documents. Every persistence, original download and export checks the active original person and current named grant. PostgreSQL migrations enforce owner RLS and immutable revision/original/export-attestation rows. Native migrations use the kernel's separately reviewed closed SQL family; PostgreSQL fixture success alone is not native-runtime evidence.

The shared inspector flushes valid pending changes before Save, export and assistant handoff. Invalid/stale drafts remain visible and block those actions. Explicit document replacement discards drafts only after the replacement has validated. On a phone the bottom bar (Format, Insert, Comment, Concierge, More; Slides or Sheets first) opens the same real controls as sheets; on a desktop Format and Concierge are tabs of one docked pane beside the canvas, so Zoom Fit always fits the page in the space left; Word opens at readable 100% zoom on narrow screens and the paper/grid pans inside the viewport.

## Import fidelity

OOXML import is bounded to 10 MiB compressed, 1,200 package entries, 6 MiB per expanded entry and 32 MiB aggregate. Active macro/embedded content, external workbook links and XML declarations/entities are refused. Embedded PNG/JPEG images are decoded and bounded before save. Imports outside the exact editor profile present conversion findings and require explicit acceptance before saving an editable copy. The **byte-exact original**, its SHA-256 and findings remain attached to that saved copy and downloadable separately across edits.

Exports contain visible editable Office content plus a private versioned model with digests of the package parts. The server records bounded original-owned attestations of the exact exported bytes and model digest for24hours (up to256 retained exports). Only an exact matching attested export restores its embedded model without conversion. Other files, expired/unretained exports and any changed private or visible package content import the actual visible Office content with a conversion report. A self-declared embedded model or package digest never grants trust.

This is a bounded editable Office profile. PowerPoint masters, groups, custom shapes, charts, diagrams and animations do not have a complete editable representation. Word uses explicit pages and basic flow, not automatic pagination, tracked changes/comments, complex fields or full section/style inheritance. Excel does not reproduce pivots, charts, merged layouts, validation, conditional formatting or every calculation function. Conversion reports identify unsupported content; the retained original preserves it. The legacy generator remains available for its advanced generated layouts. There is no claim of Microsoft Office fidelity for unsupported content.

## AI works on the same document

The actual shared `createEditorAssistant` uses the existing `deck-builder` bot endpoint and native approval-card renderer. There is no alternate provider or simulated completion. Before a turn, the browser flushes focused edits and saves the current document. The handoff names the saved record, revision and exact selection. `office-editing-contract`, `office-read-selection-part` and `office-read-model-part` expose real revision-pinned content; bounded exact chunks include a text digest. Selected image reads expose their digest and geometry without copying embedded bytes into the conversation. `office-apply-edits` is held for approval and uses the same atomic typed operations as manual editing. Real completed changes refresh into the editable document; concurrent manual drafts are retained as conflicts. Manual editing remains usable if a provider is unavailable.

## Source and verification

Browser modules live in `tools/office`; server boundaries in `routes/office-editor`. `sql-contract.json` inventories literal SQL for the native family, and `migrations/native/002-office-editor.sql` defines its physical schema. The package uses the native runtime's existing pinned Office libraries through `createRequire`/`NODE_PATH`; it imports no sibling app implementation.

`tests/office/model.test.mjs` covers atomic operations, ranges, calculations and history. `formats.test.mjs` inspects actual OOXML/native workbooks, not preview images. `store.test.mjs` uses real forced-RLS PostgreSQL with unique disposable databases/roles to prove owner isolation, CAS, retries, withdrawal and retained originals. `browser.test.mjs` exercises actual direct editing, drag/resize, rich selections, mobile validation, saves, exports and the shared saved-document handoff. Its fixture has no AI provider and explicitly refuses provider requests; these tests do not claim live-provider approval evidence. Tests are registered in `tests/test-lab.yaml` with their actual prerequisites and cleanup boundaries.
