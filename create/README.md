# Create (create) — OSHAL app package

## Local Kubernetes suite installation

Create is the experience front door; its studio packages must also be installed and
included in the person's declared composite role. Installing Create alone does not
install its optional studios. The guarded operator helper
`python3 scripts/install-create-k8s.py --revision <full-pushed-commit>` installs
Video Studio and its required Vids package, Publishing Studio and PDF Workbench
alongside the existing Create and AI Office installation in `kind-operations-lab`.
It uses the trusted native package preview/install and Create Administrator
composite with only those optional components selected.

The helper requires already-built local Publishing/PDF images. It checks their
source identities against the selected committed packages before changing the
cluster, retains image digests, preserves existing engine mappings, and uses the
native private engine relay. Renderers have CPU/memory limits, a temporary volume,
no published host port and no login or cluster-token mount. NetworkPolicy enforcement
depends on the cluster's CNI. Kernel replacement reconnects the local portal forward;
finish active sign-in or generation first. Installation is separate from actual
PDF/video export acceptance; check the studio and genuine generated bytes afterward.

The Video initializer creates its private scratch root as exactly `0700` before
the kernel starts. Kubernetes `fsGroup` makes the scratch volume inherit SGID;
without this step the root becomes `02700`, which the editor correctly refuses.
The helper preserves the strict check and never grants the editor cluster access.

Native image storage uses the original person's transaction to commit normalized
PNG bytes and immutable image metadata together. Cleanup removes eligible bytes
and metadata in the same transaction; a failed or uncertain commit never deletes
an image as compensation. Existing imported images keep their protected file
read boundary.

The initial native profile accepts images up to 8 MiB, at most 128 images, and
32 MiB of retained PNG bytes per person. It refuses additional uploads before
publication and shows the limit in the editor and brand page. PostgreSQL keeps
its existing private filesystem and 512 MiB quota. Full native storage capacity
and installed image acceptance remain open until independently verified.

## Command-line image rails (1.9.5)

Region regeneration now accepts the kernel's operator-only `antigravity-cli` image rail
(operator decision 2026-10-02). Under demo mode the kernel's storyboard image rail is picked by the
render bot's own harness, its own provider row or else the swarm default (core ADR-130 amendment),
so on a render bot that runs Antigravity the provider Create resolves is agy's own image tool on
that bot. The kernel reports that rail available
only to the deployment operator in demo mode and checks the same thing again at the bot. The
command-line transport still does not carry Create's `project.generate` permission to the bot, so
the rail serves the operator only:

- `project.generate` is checked first, unchanged.
- The resolved provider must report itself available for the caller before anything is generated.
- A caller the kernel has no provider for, or whose provider is not available to them, sees
  `configured: false` (`reason: region_edit_provider_unavailable`, no provider named) on
  `GET /api/create/region-edit-provider`, and their edit fails `region_edit_provider_unavailable`.
  No other provider is tried, nothing is generated and nothing is charged. Before 1.9.5 the
  provider report answered 503 `project_service_unavailable` when the kernel had no provider
  for the caller, such an edit failed as `region_edit_provider_failed`, and an edit was generated
  on a provider that reported itself unavailable.
- `codex-cli` stays refused for everyone.

No permission, catalog, migration or `authorization.yaml` change. See
[EDITOR.md](EDITOR.md#region-regeneration-190).

## Region-edit cost consent (1.9.4)

The provider report advertises `costConsentVersion: 1`; new clients can submit
`maxCostClass: 'free' | 'paid'` on an edit. The actual post-queue provider must
respect that cap before generation. Omitted caps preserve legacy behavior, so new
acceptance clients must require the version before any fixture writes and always
send their cap. The editor captures the displayed class before asynchronous save,
and a refusal refreshes the disclosure without retrying or escalating.
See the [contract and compatibility boundary](EDITOR.md#cost-consent-for-region-regeneration-194).
No permissions or catalog bindings change.

## Region editing in the editor (1.9.1)

Select a region, describe the change, and **Regenerate region**; compare the
candidate side by side, then accept it as a new revision (undoable) or reject it. The
panel says what will be sent and what it costs first. See
[changing a region](EDITOR.md#changing-a-region-in-the-editor-191). Local proof only;
installing needs the 1.9.0 reviewed catalog migration.

## Region regeneration (1.9.0)

Regenerate only a selected region of an image layer into a candidate you accept,
reject or cancel. Outside the region the image is byte-identical; accepting appends one
revision on the revision you hold and keeps your manual edits. Generating is the new
`project.generate` permission (`generator` or `admin` role); spend lands in the cost
ledger. See [region regeneration](EDITOR.md#region-regeneration-190). Installing needs
the reviewed authorization catalog migration. Local proof only.

## Access (ADR-149)

Before a studio is offered, the New screen and Home ask the authorization service what the
signed-in person may open (`GET /api/authorization/me?app=<member>`): `legacy` is open; an enforced
package is open only when the person's tier is not deny. A studio that is not provisioned renders
**locked** — it never opens and its Home probe is never asked — with the Access link an administrator
uses (`/access?app=<member>`). A probe that cannot answer is marked "can't check" and left in place.
The rail tiles themselves are manifest-static; opening a locked studio from the rail lands on the
kernel's role-guidance page.

## The skin, and what wears it

Since **1.2.2**, Home and New follow the selected portal palette, including Workspace,
through the shared theme bootstrap and CSS. Changing the theme keeps the same document,
search input and studio links. Standalone pages follow the saved choice and changes from
other tabs; with no saved choice they start in Workspace without writing a preference.

Enable **Application colors** in Cockpit Settings to wear the original `ui/create.css`
skin. The profile supplies `themeCssUrl`, and both surfaces retain the package stylesheet
at `/api/create/theme/create.css`. This opt-in never overwrites the saved portal palette;
choosing a portal theme turns application colors off again. The page's initial Create
attribute remains a fallback for a host without the shared bootstrap.

An iframed member studio derives its palette from the framework tokens through the
shared `surface-theme.js` bootstrap. Cores that include the bundled-skin follow (the
bootstrap reads the same-origin parent's `data-theme` + `#app-package-theme-css` link)
render the studios in the Create skin too; an older core renders them in the operator's
saved theme, which is the framework's pre-existing behaviour — never a broken page.

## Brand Kit (1.8.0)

The contract, the file map, every test command, the installation gate and the next slices are in
[BRAND-KIT.md](BRAND-KIT.md).

One private brand kit per person, edited on the **Brand Kit** tile (`/api/create/brand`) and read
by every studio in the viewer's own session. It holds a brand name, five role colors (primary,
secondary, accent, text and background) plus up to six named extras, a heading and a body face
from the fonts that ship with Office on Windows and macOS, a one-line voice, and a logo.

- **Storage.** `migrations/002-create-brand-kits.sql`: one row per verified issuer and subject,
  optimistic revisions, the same exact-owner row security as projects. The logo is an ordinary
  owned Create image (same normalization, quota and storage); the database refuses a logo that
  belongs to someone else, and unused-upload cleanup keeps an image a kit uses.
- **Routes** (inside the project router): `GET /brand-kit` (the kit, its revision, `canChange`
  and the colors in words), `PUT /brand-kit` (`{ baseRevision, kit }`; 0 for a first save, a stale
  page gets 409), `DELETE /brand-kit` and `POST /brand-kit/logo`. The server validates with the
  same `tools/editor/brand-kit.mjs` module the page runs.
- **Permissions.** Its own `brand` resource: `brand.read` for every role that reads projects,
  `brand.change` for editor and admin. Viewer-tier roles never write.
- **Where it shows up.** The image editor opens templates in the brand (colors by role, bold text
  in the heading face, the name on the signature line, the logo in each design's logo slot, and
  text re-inked when it would lose contrast), offers the brand swatches and faces beside every
  layer, and adds the logo as a layer without a new upload. Home shows the kit or a setup prompt.
  AI Office (2.13.0) draws decks, documents and workbooks in the brand's exact colors and faces
  through the look **Your brand**, which the core deck engine builds on the nearest built-in
  look's layout and which is picked when nothing else chose a look. It also fills an empty cover
  byline with the brand name and can add the brand voice to AI drafts. Portrait Studio and Video
  Studio offer a **Use my brand colors** button that adds the colors, in words, to the notes or
  style field.
- **Limit.** AI Office keeps the cover and decoration of its nearest built-in look and does not
  place the kit's logo in the file.

## Agent editing — 1.14.0 source delivery

`create-editor` is the package's inline editing concierge, reachable through
the shell's Concierge control. Its manifest declares six
original-caller API tools: editing-contract, list/read projects, create a blank
project and apply bounded edits plus editable JSON export. Raster and SVG rendering
remain the editor's explicit controls.

An edit uses the actual saved project id and `baseRevision`. At most 16 operations
and 16 KiB produce one immutable revision; a failed batch saves nothing. Existing
model validation, owner/source checks, layer/track locks and optimistic concurrency
apply. Agent booleans permit one operation per batch and 256 total operand nodes;
larger booleans use the editor worker. Both read and change permissions are rechecked before commit. The kernel's
existing write approval cards show the exact proposed input; the agent reports
success only after the real route response. In the 1.15.2 source, the editor automatically saves
the current browser draft before the concierge reads it and refreshes the same project on return.
The next manual change is saved at the next handoff. Concurrent browser drafts are preserved
with an explicit conflict, and the concierge edit enters local undo history as one edit.

The installed `/api/create/editing-contract` returns the supported forms, examples, units and limits.
No shell, arbitrary code, remote fetching or new provider pipeline is exposed.
The separate RAW, publishing, audio and PDF domains remain outside this editor; bounded PSD import source delivery is described below.
Catalog bindings and the new personas require a reviewed reload/install and native
acceptance; source proof does not claim that these agents are live. No deployment
or service restart is part of this delivery.


## Bounded editable PSD import (1.15.0 source delivery)

Use **Import PSD** or **PSD from OSHAL files** in the Image editor. Inspection
saves nothing. Review the conversion findings, choose editable layers/groups or
an explicitly flattened merged image, then **Import and save**. The original
canvas is protected while reading/reviewing; cancelled reviews publish nothing.
The resulting project uses existing image references, layer properties, group
transforms, undo/redo and immutable save/reopen. **PSD original and report** opens
its import lineage; **Download PSD original** requires a separate current export
grant and returns exact original bytes. Later edits never rewrite that original.

This subset accepts RGB8 PSDv1 raw/PackBits:4MiB input,2048 pixels/side,4M canvas
pixels,32 pixel layers/64 records,4 normal isolated group levels,8M total decoded
pixels. Retained originals total4MiB per person independently of the native32MiB
PNG profile; each import permits at most16MiB normalized PNGs. Two whole request
pipelines and two10s parser workers are admitted, with explicit busy refusals.
Normal groups become fixed-frame groups: later child movement outside the frame
clips it, reported before import. Transparency locks become deliberate whole-layer
locks with a report. [Format matrix](specs/functional-gaps/psd-format-matrix.md)
lists unsupported semantics and transparent merged-cache limitations. PSD export,
PSB/high bit depth, ZIP, other blends, masks, text/effect/smart-object editing and
full Photoshop fidelity are not delivered. Opaque unsupported semantic payloads
remain in the original; this profile does not decode their descriptors.

Agents inspect a real protected artifact with `create-inspect-psd`, explain losses
and the chosen mode, then propose `create-import-psd` through the held approval
card using that actual inspected SHA. No paths/URLs/owners or arbitrary code are
accepted. One UUID4 request key seals bytes, mode and title; uncertain transport
retries preserve that key and do not duplicate projects/assets. A replay returns
the immutable first import, so subsequent edits always read the current project.
`create-psd-source` reads the source report; native Create JSON/raster exports
remain their existing formats.

Source proof: genuine binary spec fixtures plus licensed immutable Pillow10.2.0
corpus, exact independent raster-plane decoding, real Sharp PNG/forced-RLS

## Automatic document handoff — 1.15.2 source

The shared kernel document handoff is used by Concierge and Jarvis. Create registers its
existing authorized save and read functions: handing over automatically saves the current
draft, including a focused field, and provides the saved project identity, revision and
selection. A completed turn or approved edit refreshes the same project. No Save or Reload
step is required. Failed saves stop the handoff. If the person edits while the concierge
is working, refresh retains that draft and reports the conflict instead of replacing it.

`tests/browser/create-handoff-proof.mjs` exercises the actual editor, original-owner project
operations and a disposable PostgreSQL role with row security. It covers repeated manual/assistant
turns, editable gray adjustment and text layers, failed saves, undo and concurrent drafts.
Run it with the declared browser/runtime prerequisites; Test Lab recipe `document-handoff`.
Source verification is separate from installed acceptance, which is pending for this release.
