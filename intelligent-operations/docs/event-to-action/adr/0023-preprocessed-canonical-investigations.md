# ADR0023: Link evidence to the canonical investigation workflow

Implemented and native24d62980 accepted, 21 October 2026. The operating-experience receipt proves actual first-phase inference and shared-workspace output.

An evaluated, admitted symptom with a capture reservation can pin its preprocessed context and prepare a canonical Intelligent Operations ticket through the original user's native ticket service. The application stores one durable association per immutable reservation. It records a creating marker before the external create call, deduplicates concurrent requests and holds unknown outcomes for reconciliation rather than blindly creating another ticket. A lost link acknowledgement reconciles the already saved exact ticket ID.

The operator starts investigation from Data & decisions. Preparation returns one fixed evidence/packet.json, canonical JSON bytes and SHA-256 digest, plus the bounded original-owner dispatch input. The browser uses the existing canonical ticket start API with the user's portal session. Existing workflow phases and shared workspace persistence generate the accepted answer artifacts. No separate incident engine, cluster credential, raw stream handle or infrastructure executor is introduced.

Funnel metrics join exact delivery/reservation/ticket IDs. An AI assessment counts only a completed first-phase native work record with a released nonempty answer and inference receipt. Canonical done means report acceptance. Verified infrastructure recovery remains an explicit unconnected stage until a real recovery-check receipt exists. Unknown/unreadable work remains unavailable, not zero; unrelated tickets and repeated evaluations cannot inflate the cohort.

The UI refreshes workflow progress on request and clears private content on access refusal. This increment does not add automatic background investigation dispatch, multi-file remediation generation, execution approvals, recovery verification, external ticket status sync or outbound messaging. Those are distinct active build gates, not implied by a created or completed ticket.

Proof: real PostgreSQL tests cover concurrent preparation, owner isolation, unknown creation and lost commit acknowledgement. The actual shipped browser verifies sealed-byte dispatch, idempotent resume, receipt-based counts and refusal clearing against an explicit canonical-service fixture. Live native inference and workspace acceptance are recorded separately after deployment.
