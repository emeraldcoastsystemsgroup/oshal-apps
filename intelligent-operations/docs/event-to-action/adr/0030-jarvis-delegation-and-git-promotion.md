# ADR0030: Plan Git-backed Jarvis delegation and promotion

Status: proposed roadmap, 21 October 2026. No hierarchy implementation is claimed.

The operator requested Git connectivity and upper/lower swarm cooperation: repair
and prove changes in a lower environment before promoting them to the upper one.
Adopt the staged scope in [the promotion roadmap](../SWARM-PROMOTION-ROADMAP.md).
Use standard user-bound connections, canonical linked tickets/workspaces and
registered swarm identities. Preserve distinct identities and authority at every
hop. Promotion binds approval and evidence to an exact commit and build digest.

Reusable delegation, authority, durable transport and recovery belong in the
platform where gaps are demonstrated. Incident policy and the visible promotion
journey belong in TriageNorth. Existing ticket synchronization is not Git change
execution. A child's successful result is evidence for an approval, not a grant.

H1–H5 define delivery dependencies and positive/refusal acceptance. This decision
adds planning and connection shortcuts only; it enables no autonomous deployment.
