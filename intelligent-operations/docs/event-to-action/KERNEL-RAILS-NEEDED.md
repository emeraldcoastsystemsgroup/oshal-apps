# Kernel rails the remaining requirements need

Recorded 22 October 2026 after reading the native kernel on `dev/native-parity` (merged to main
as e7763d8). Each row is something the Intelligent Operations package cannot do on its own
because the kernel exposes no rail for it. The package side is designed and, where possible,
already built to adopt the rail (review first, exact binding, operator-reported versus
server-verified labels). Rows marked Built have their kernel rail and package side in place; the others are not claimed.

| Capability Roger asked for | What exists | What the kernel needs | Package side |
|---|---|---|---|
| Run `aws` / `gcloud` / `az` / `kubectl` from the application under the person's authorization | **Reads built for all three clouds.** AWS through the `awsSigV4` connector: STS identity, EKS clusters and node groups (ADR0042). Google Cloud through `gcp`: GKE clusters and node pools. Azure through `azure`: subscriptions, AKS clusters and agent pools (ADR0045, kernel PR 82). The native node runs without host network or profiles | Writes and more services as curated entries; an operator-registered OAuth client for Google and for Azure; or a reviewed CLI envelope on the person's OSHAL Node | Command helper runs the supported reads through the person's own connection; everything else is coached and recorded |
| Shell on a host (SSH) | **Built (kernel ADR-195, PR 84):** a native `ssh` connector. An administrator selects literal-address hosts with pinned host keys, and a person uses their own ed25519 key. `ssh-exec` runs one reviewed, quoted argv per confirmation (30 s, 64 KiB). No tunnels | Response-plan execution on hosts; host discovery | Command helper runs a coached host command on a selected host (ADR0047) |
| Live cluster explorer (nodes, namespaces, pods across clusters) | **Built (ADR0041).** `kubernetes-list-nodes`, `-list-pods` and `-list-deployments` on kernel `dev/native-parity` d033905, installed on the lab: bounded summaries under the person's connection, node reads through a node-only ClusterRole | `-list-namespaces` and a per-person multi-cluster service selection | Systems Live cluster panel reads, shows and saves a live scan in its own collection |
| Scheduled discovery (R15) | **Built (kernel ADR-196):** `connector.read`, an application's read under the caller's own connection, granted per connector at consent (`connector.read.kubernetes`); writes and confirmed effects are refused | Namespace listing; per-person multi-cluster selection | The processing tick reads the chosen cluster and namespace once per interval and saves the live scan (ADR0049) |
| Git integration: branch, commit, pull/merge request, pipeline trigger and status | Added as connector catalog configuration on kernel `dev/native-parity` 0f86a3c (GitHub tree/commit/ref/pull/workflow dispatch/runs/check runs; GitLab branch/commit/merge request/pipelines), confirmation-gated, guarded | **Built and installed on the lab** (kernel PRs 85 and 86: explorer reads, User-Agent); the GitHub service is selected and the person saves their own token. Nothing further from the kernel | Git promotion and break-glass reconciliation (ADR0040), provisioning (ADR0044) and the Git explorer (ADR0048) built and guarded; live acceptance waits on a valid GitHub token (the saved one is refused with 401) |
| Break-glass runtime patch with expiry | The approved exec (ADR0037) is the patch; reconciliation in Git with a 24-hour deadline is in the package (ADR0040) | Nothing further for the lab; a kernel-registered expiry action would let the deadline be enforced server-side | Overdue reconciliations are shown; enforcement is by the operator |
| Swarm-to-swarm over Jarvis (lower monitoring swarm) | **Inbound built (kernel ADR-194, PR 81, on the lab):** peer tokens (confirmed, digest-only), `POST /a2a/v1/delegations` with a peer-token bearer, a closed bounded envelope, an owner-only inbox; outbound through a curated `oshal-peer` connector | A public agent card; acknowledgement back to the sender; private-network peers (the connector rail reaches public HTTPS only); naming a swarm through Jarvis | Swarm hand-off page sends a plan, files received delegations as investigations, manages peer tokens (ADR0043); Jarvis answers about hand-offs and attention through read-only tools (ADR0046) |
| Automatic ticket dispatch from a capture reservation (R20) | **Built (ADR0041).** `ticket_start` on the package port, kernel `dev/native-parity` 3200d5c, installed on the lab: same admission as the person's own start plus package ticket-type ownership | Nothing further | The processing tick starts at most two investigations per tick with the opt-in; uncertain starts are held, never retried |
| Automatic external ticket synchronization with attested receipts (R24) | Browser-confirmed connector actions; server-side egress works only for gitlab.com with an installation key, Jira/ServiceNow hosts are not bound | Package-callable connector actions under the person's own account with kernel-recorded receipts | Outbox design in ADR0025; manual handoff exists |
| Notification delivery receipts (R06) | `ctx.notify` requests delivery; silent skips return success | A delivery receipt (channel, address class, accepted/skipped reason) | The tick already records the request and labels it |
